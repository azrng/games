# 冰火神庙：桌面复刻游戏接入网页平台

## 项目背景

《冰火神庙》为森林冰火人四神庙系列（forest/light/ice/crystal 四包共 158 关）的 Phaser 复刻，已作为 Electron 桌面应用在独立仓库（Gitee fw-temples）完成开发与交付。现需让该游戏无需安装即可在网页平台游玩：以 web 版形态接入本平台游戏大厅。

## 目标与范围

- 目标：在平台大厅新增「冰火神庙」入口，点击即玩，进度保存在浏览器本地。
- 范围内：
  - 四包 158 关全部上线（forest 32 / light 42 / ice 44 / crystal 40）。
  - 主菜单、选关、设置、对局历史、进度存档、重置进度等既有页面能力在 web 版可用。
  - web 版可从游戏内返回平台大厅。
- 范围外：
  - 不合并 fw-temples 源码仓库；桌面版继续在原仓库独立迭代。
  - 本次为一次性移植，不做自动同步；后续桌面版更新经手动重跑构建脚本同步。
  - 不改造游戏本体玩法、关卡数据与素材；不支持移动端触屏操作。

## 用户角色

- 平台访客：在大厅浏览并进入游戏，无需注册登录。
- 玩家：键盘双人操作（火男 WASD / 水女方向键），进度与设置本地留存。

## 页面清单

| 页面 | 说明 |
| --- | --- |
| 大厅入口卡片 | 平台首页游戏清单新增一条目 |
| 游戏选择页 | 四包选择（沿用桌面版首页） |
| 神庙主菜单 | 开始 / 选关 / 设置 / 返回大厅 |
| 选关页 | 分包关卡网格、解锁与通关徽章 |
| 游戏页 | Phaser 双人关卡游玩 |
| 设置页 | 音乐 / 音效音量、重置进度 |

## 核心业务流程

1. 大厅点击「冰火神庙」→ 进入游戏选择页。
2. 选择神庙包 → 主菜单 → 选关页 → 进入关卡游玩。
3. 过关 → 结算（用时/钻石）→ 进度保存 → 解锁下一关。
4. 主菜单可返回平台大厅。

## 关键业务对象（业务语义）

| 对象 | 业务含义 |
| --- | --- |
| 关卡进度 | 每关：是否解锁、是否通关、历史最佳用时、红钻并集计数、蓝钻并集计数 |
| 设置 | 音乐音量、音效音量（0~100） |
| 对局历史 | 每局：关卡、用时、红/蓝钻、时间；按包留最近 20 条 |
| 重置进度 | 清空全部四包进度与对局历史；音量设置保留 |

## 权限与可见范围

无账号体系，全部数据存于浏览器本地，仅当前浏览器可见。

## 边界场景与异常

- 存储不可用（隐私模式等）：游戏可进入，进度保存失败给出错误提示与重试入口（与桌面版保存失败语义一致）。
- 清浏览器数据 = 清空进度，属浏览器既有行为，不做补偿。
- 「退出」按钮在 web 版无退出语义，保留但点击无副作用。

## 非功能要求

- 平台保持零构建模式；游戏以静态产物进入 `src/<slug>/`。
- 存储键名符合平台规范 `app_game_<slug>_<field>`。
- 产物总体积控制在素材既有规模内（约 14MB，主要为核心音效与精灵图）。

## 验收标准

1. 大厅出现「冰火神庙」卡片（电脑端 Tab 可见），点击进入游戏选择页。
2. 四包均能进入选关页并正常装载关卡；抽样关卡可操作、可过关。
3. 过关后刷新页面进度仍在；重置进度后回到初始解锁态且音量保留。
4. 平台体检脚本（audit-games.js）零错误；存量 smoke 测试全绿。
5. 游戏内主菜单可返回平台大厅。
