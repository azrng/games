# 动物翻翻棋 · 核心玩法（REQ-AFC001）

> 迁移自 `doc/requirement.md` 第五章（2026-10-08 按模块拆分）。功能已交付（`src/animal-flip-chess/`），实际实现为「玩家 vs 电脑 AI」对战（需求中的本地双人模式与猜拳先手被 AI 对手取代，人机先手随机）；本文档作为已交付需求的记录基准；原「待确认项」保留为历史记录。

## 项目背景

动物翻翻棋源自童年纸牌版「斗兽棋翻棋」，是一款结合翻牌博弈与大小克制关系的对战休闲游戏。16 张牌背面朝上随机摆放，双方轮流翻牌或移动，利用动物等级克制关系吃光对方棋子即可获胜。规则简单但策略性强，"老鼠吃象"的反转机制是核心乐趣点。

## 目标与范围

- 目标：为游戏平台新增一款动物翻翻棋游戏，支持翻牌与移动双操作、完整战斗判定和胜负结算。
- 范围：单页面游戏，不涉及用户登录或在线排行榜。首期需求为本地双人对战 + 猜拳决定先手；实际交付改为玩家对电脑 AI（先手随机），双人模式列入历史待确认项。

## 用户角色

- 玩家：与电脑 AI 在同一页面轮流操作（实际交付）；需求原版为两名玩家在同一设备上轮流操作。

## 棋子设定

共 16 张牌（双方各 8 张），每方各 8 种动物各 1 张：

| 等级 | 动物 | 特殊说明 |
|------|------|----------|
| 8 | 象 | 最大，但被鼠吃 |
| 7 | 狮 | |
| 6 | 虎 | |
| 5 | 豹 | |
| 4 | 狼 | |
| 3 | 狗 | |
| 2 | 猫 | |
| 1 | 鼠 | 最小，但可吃象 |

克制规则：
- 己方等级 ≥ 敌方等级 → 可吃掉敌方（移动时判定）。
- 鼠(1) vs 象(8) → 鼠胜，象被吃（唯一越级克制）。
- 同级 → 同归于尽，双方牌均从棋盘移除。
- 己方等级 < 敌方等级 → 不能移动到该格。

## 棋盘与布局

- 4×4 方格，共 16 个格子。
- 所有牌背面朝上，随机洗牌后均匀放置到 16 个格子中。
- 不区分阵营初始位置，牌的归属在首次被翻开时确定。

## 游戏流程

### 先手决定

- **需求原版（本地双人）**：开局进入猜拳阶段，红蓝双方各选石头/剪刀/布，双方都选择后判定，胜者先手，平局重猜。
- **实际交付（人机对战）**：无猜拳阶段，开局先手方随机决定，电脑先手时有思考提示。

### 游戏主循环

先手方开始，双方交替进行回合。每回合玩家**二选一**操作：

**操作一：翻牌**
- 点击任意一张背面朝上的牌。
- 牌以翻转动画翻开，显示动物和阵营颜色。
- 无论翻到己方还是敌方牌，回合立即结束，轮到对方。

**操作二：移动（吃子）**
- 点击一张已翻开的己方牌 → 牌高亮选中，可移动的相邻格高亮。
- 再点击一个高亮格执行移动：
  - 目标格为空格 → 直接移动过去。
  - 目标格为敌方牌且己方等级足够 → 吃掉敌方，己方占据该格。
  - 目标格为敌方牌但己方等级不够 → 不可移动（该格不高亮）。
  - 同级 → 同归于尽，双方均移除。
  - 鼠 vs 象 → 鼠吃象。
- 移动方向：仅上下左右四个正方向，不含对角线，每次移动一格。
- 移动/战斗完成后回合结束，轮到对方。

### 胜利条件

- 吃光对方所有棋子 → 获胜。
- 对方无任何合法操作（无暗牌可翻且无合法移动）→ 获胜。

## 关键业务对象及字段

| 数据项 | 存储方式 | 说明 |
|--------|----------|------|
| 棋盘状态 | 页面内存 | 4×4 数组，每格记录：牌的动物等级、归属方、是否翻开、是否已被吃 |
| 当前回合方 | 页面内存 | 先手/后手交替 |
| 游戏阶段 | 页面内存 | 开局 → 对局中 → 结束 |
| 选中状态 | 页面内存 | 当前选中的己方牌坐标（移动操作时） |
| 双方剩余牌数 | 页面内存 | 实时统计 |
| 暗牌数量 | 页面内存 | 剩余未翻开的牌数 |
| 总回合数 | 页面内存 | 用于结算展示 |
| 胜负记录 | localStorage | 双方胜场，前缀 `flip-chess-`（需求原版；AI 对战版本以实现为准） |

## 交互说明

- 进入游戏即开始对局（实际交付为先手随机；需求原版为先猜拳决定先手）。
- 顶部状态栏显示当前回合方；电脑回合有思考中提示。
- 翻牌：点击暗牌后以 CSS 3D 翻转动画翻开，回合自动结束。
- 移动：点击己方牌选中 → 高亮可移动格 → 点击目标格执行。点击非高亮区域取消选中。
- 战斗动画：吃子时攻击方过渡到目标格，被吃方缩小消失；同归于尽时双方同时消失。
- 游戏结束弹出结算面板，显示获胜方、双方剩余牌数、总回合数。
- "再来一局"清空状态重新开局。

## 边界场景与异常

| 场景 | 处理方式 |
|------|----------|
| 翻到己方牌 | 回合直接结束，轮到对方 |
| 翻到敌方牌 | 回合直接结束，轮到对方 |
| 选中己方牌但无可移动目标 | 无高亮格提示，点击其他位置取消选中 |
| 所有暗牌翻开 | 进入纯移动阶段，只能移动已翻开的牌 |
| 一方无暗牌且无合法移动 | 判定该方失败 |
| 快速连续点击 | 操作锁定，动画期间不接受新输入 |
| 猜拳平局（需求原版） | 自动重新猜拳 |

## 非功能要求

- 页面首屏加载 < 1s（纯静态资源，无外部依赖）。
- 翻牌动画使用 CSS 3D transform。
- 棋盘使用 CSS Grid 渲染，格子为正方形，响应式适配。
- 移动端触控目标最小 44×44px。
- 支持 iOS Safari 和 Android Chrome 最近两个主版本。
- 视口设置 `width=device-width, initial-scale=1.0, user-scalable=no`。

## 验收标准

> 以下标准为迁移时依据原文流程、边界与既有实现归纳补充。

1. 开局 16 张暗牌随机洗牌布满 4×4 棋盘，双方各含 8 种动物各 1 张。
2. 翻牌后归属方确定，回合立即交给对方；移动仅限上下左右一格，受克制规则约束（含鼠吃象、同级同归于尽）。
3. 等级不足时目标格不高亮、不可移动；同归于尽目标有独立视觉标识。
4. 吃光对方棋子或对方无合法操作时判胜，结算面板展示获胜方、双方剩余牌数与总回合数。
5. 动画期间操作锁定，不接受连点输入；电脑回合展示思考状态。
