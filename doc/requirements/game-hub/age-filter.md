# 游戏平台首页 · 年龄筛选 Tab（REQ-GH001）

## 背景

首页当前把全部游戏平铺展示。随着游戏数量增长到 16 款且受众明显分化（儿童学习向、成人英语自学向、全龄休闲向），家长为孩子挑游戏、成人用户找适合自己游戏时都缺少定位手段。需要一个轻量的年龄筛选入口，不改变游戏本身，只帮助收窄浏览范围。

## 目标与范围

**本次覆盖**：
1. 首页标题与游戏列表之间新增年龄筛选 Tab：「全部 / 儿童 / 成人」，默认「全部」。
2. 筛选语义为「适合该人群」的包含关系：
   - 「全部」= 所有游戏（16 款）。
   - 「儿童」= 儿童专属 + 全龄（隐藏成人向游戏）。
   - 「成人」= 成人向 + 全龄（隐藏儿童专属游戏）。
3. 每款游戏在数据层标注适龄分类，分类缺失时按「全龄」兜底展示（不隐藏）。
4. Tab 上展示当前分类的游戏数量，数量由数据实时推导，不硬编码。

**本次不覆盖**：游戏卡片上的适龄徽章、更细的分龄档（如 3-6 / 6-12 / 12+ 三档以上）、筛选状态持久化（刷新恢复所选 Tab）、单游戏页任何改动。

## 用户角色

- 家长：为 3-12 岁孩子筛选合适游戏，不希望看到成人学习类游戏。
- 成人用户：自学或休闲，希望隐藏低龄向游戏。
- 儿童用户：直接浏览，默认看到全量中适合的部分。

## 页面 / 模块清单

- 平台首页 `index.html`（Tab 区域新增）
- 数据层 `src/data/games.js`（目录条目增加适龄分类）
- 渲染层 `src/js/app.js`（筛选与重渲染逻辑）
- 样式 `src/css/custom.css`（Tab 样式与移动端适配）

## 核心业务流程

1. 进入首页，默认「全部」Tab 选中，展示全部游戏。
2. 点击「儿童」：列表收窄为儿童专属 + 全龄游戏。
3. 点击「成人」：列表收窄为成人向 + 全龄游戏。
4. 点击「全部」恢复完整列表；刷新页面回到默认「全部」。

## 关键业务对象：适龄分类

游戏目录条目新增「适龄分类」字段，取值三选一：

| 取值 | 含义 | 首页哪些 Tab 可见 |
| --- | --- | --- |
| `kids` | 儿童专属（内容面向 3-12 岁） | 全部、儿童 |
| `adult` | 成人向（内容面向 12 岁及以上） | 全部、成人 |
| `all` | 全龄（无明确年龄倾向） | 全部、儿童、成人 |

初始归类（用户可逐项调整）：

| 游戏 | 归类 | 理由 |
| --- | --- | --- |
| 找猫咪、动物翻翻棋、数学小勇士、点字成诗、拼音打字乐园 | kids | 找猫涂色、动物棋、小学口算、小学古诗、拼音打字启蒙 |
| 单词大炮 | adult | 成人英语学习定位（四六级/职场词包） |
| 其余 10 款（2048、五子棋、俄罗斯方块、迷宫冒险、色觉挑战、数字华容道、一笔画、转管道、点灯、扫雷） | all | 通用益智/经典玩法，无年龄倾向 |

## 权限与可见范围

无权限模型。筛选仅影响首页展示，不影响任何游戏的可用性与链接。

## 边界场景与异常

- 目录数据缺失或为空：维持现状（不渲染列表），Tab 区域也不渲染。
- 某分类下没有游戏：列表区显示空态提示文案，不显示空白。
- 条目缺少分类字段或取值非法：按「全龄（all）」兜底，保证游戏不被错误隐藏。
- 移动端：Tab 可换行或横向滚动，卡片上的玩法标签保持现有移动端隐藏策略。

## 非功能要求

- 保持无构建、无后端、无新增第三方依赖；静态打开首页即可用。
- 筛选为纯前端同步过滤，切换无感知延迟；不引入 loading 状态。

## 验收标准

1. 默认进入首页「全部」选中，展示 16 款游戏。
2. 点「儿童」后列表为 15 款，其中不含「单词大炮」；含全龄游戏与 5 款儿童专属游戏。
3. 点「成人」后列表为 11 款，其中不含 5 款儿童专属游戏；含「单词大炮」与全龄游戏。
4. 三个 Tab 的数量文案与实际渲染卡片数一致。
5. 刷新页面回到「全部」；Tab 支持键盘聚焦与回车切换。
6. 将某款游戏的分类字段删除或改为非法值后，该游戏在三个 Tab 下均可见（兜底生效）。
