# 游戏平台 · 游戏页首次进入玩法提示（REQ-GH003）

## 背景

平台游戏已达 36 款，其中只有记忆翻牌（memory-match）做了首次进入的玩法提示条；多数游戏点进去没有任何指引，只能自己试。本仓游戏大量面向低龄用户，一批游戏的交互方式并非通识：七巧板要点板再点剪影、编程小机器人要先编排指令再运行、天平称重要做等量代换、倒水谜题要在无刻度杯子间倒水。首次进入时缺一句说明，儿童用户和家长陪玩都容易懵。游戏大厅卡片虽有一句话简介（`desc`），但那是「这是什么游戏」，不是「这一局怎么玩」。

## 目标与范围

**本次覆盖**：
1. 新增游戏页共享组件 `src/js/game-tip.js`：首次进入在游戏内容顶部展示玩法提示条，点「知道了」后记入存档，之后进入不再自动展示。
2. 游戏页头常驻「?」按钮，任何时候可重新展开玩法提示条，错过或误关后也能找回。
3. 组件范式与 `game-back.js` 一致（样式自包含注入、游戏页只加一个带配置的 script 标签），游戏逻辑脚本与组件零耦合。
4. 接入 11 款交互不直观的游戏：一笔画、天平称重、倒水谜题、编程小机器人、购物小掌柜、动物翻翻棋、七巧板、时钟认知、图案找规律、数织、汉字拼字（后 5 款因与 T061 修复批次同批文件，待其收口后于同日晚间补接完成，接入方式零差异）。

**本次不覆盖**：
- 记忆翻牌已自带的提示条保持现状，不替换为共享组件（避免无行为收益的回归面）。
- 已带常驻页内说明的游戏（2048、打字大炮、点字成诗等）的说明形式统一，留待后续批量对齐。
- 「玩法通识」游戏（贪吃蛇、俄罗斯方块、扫雷等）的接入，视首批效果后续再定。

## 用户角色

- 儿童用户：首次进入即知道第一步做什么，不会被陌生交互卡在开始前。
- 家长：陪玩时无需试错就能向孩子解释规则；误关提示后可通过「?」找回。

## 页面 / 模块清单

- 共享组件 `src/js/game-tip.js`（新增，含注入样式与存档读写）
- 组件测试 `src/js/game-tip.smoke.test.js`（新增）
- 首批 6 款游戏页 `src/<slug>/index.html`（各加一个 script 标签与文案配置）

## 核心业务流程

1. 首次进入游戏页：内容顶部自动展开玩法提示条（一到两句、动词开头的操作说明），页头出现「?」按钮。
2. 点「知道了」：提示条收起，关闭状态写入 localStorage（键 `app_game_<slug>_howto_seen`），刷新后不再自动展示。
3. 点「?」：重新展开提示条（无论是否关闭过），再点「知道了」收起且不再改变存档语义。
4. 换一款游戏互不影响：存档按游戏 slug 隔离。

## 关键业务对象：提示关闭标记

| 项 | 值 | 说明 |
| --- | --- | --- |
| 存储键 | `app_game_<slug>_howto_seen` | 命名沿用 `store.js` 的 `buildGameKey` 约定，audit 工具可按前缀识别归属 |
| 值 | `'1'` | 存在即视为「已关闭，不再自动展示」；缺失/其他值一律视为首次 |
| 降级 | localStorage 不可用时退回内存 | 当次会话内关闭仍生效，不报错；下次进入重新展示 |

## 权限与可见范围

无权限模型；所有用户一致。提示条为非阻断形态（非弹窗），不拦截游戏交互，不出现于弹窗遮罩之上。

## 验收标准

1. 首批 6 款游戏首次进入均自动展示对应玩法的提示条，文案与该游戏实际交互一致。
2. 点「知道了」后刷新页面不再自动展示；点「?」可再次展开。
3. 隐私模式等存储不可用场景：页面加载与关闭操作均不报错。
4. 组件 smoke（`src/js/game-tip.smoke.test.js`）与全仓 `tools/run-all-smoke.js`、`tools/audit-games.js` 通过。
