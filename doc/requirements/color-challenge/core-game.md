# 色觉挑战 · 核心玩法（REQ-CC001）

> 迁移自 `doc/requirement.md` 第一章（2026-10-08 按模块拆分）。功能已交付（`src/color-challenge/`），本文档作为已交付需求的记录基准；原「待确认项」保留为历史记录。

## 项目背景

色觉挑战是一款考验色觉辨识力的休闲小游戏，玩家需要在一片颜色相近的方块网格中找出颜色不同的一块。随着关卡推进，色差逐渐缩小，难度持续上升。该游戏规则极简、上手即玩，适合碎片化时间消遣，同时具备较强的社交传播属性。

## 目标与范围

- 目标：为游戏平台新增一款纯移动端的色觉挑战游戏，玩家通过触控点击完成每一轮辨识，系统自动计分、计关、计存活时长，最终以最高分和最长存活时间作为成绩记录。
- 范围：仅实现移动端单页面游戏，不提供 PC 端适配；不涉及用户登录、排行榜等社交功能。

## 用户角色

- 玩家：所有通过移动端浏览器访问游戏平台的用户，无角色区分。

| 页面 | 路径 | 说明 |

| 色觉挑战游戏页 | `src/color-challenge/index.html` | 单页面承载全部游戏状态 |

## 核心业务流程

### 游戏主循环

1. 系统生成 N×N 的颜色方块网格，所有方块为同一颜色，其中随机一块为"不同色"方块。
2. 玩家点击认为不同色的方块。
3. 判定结果：
   - **正确**：得分 +1，进入下一轮。下一轮网格可能变大（方块更多）或色差更小。
   - **错误**：游戏结束，展示本局得分、最高分、存活轮数。
4. 玩家可点击"再来一局"重新开始。

### 难度递进机制

- **第 1–5 轮**：2×2 网格，色差较大，热身阶段。
- **第 6–10 轮**：3×3 网格，色差适中。
- **第 11–20 轮**：4×4 网格，色差进一步缩小。
- **第 21–30 轮**：5×5 网格，色差极小。
- **第 31 轮起**：6×6 网格，色差极微，考验极限辨识力。

> 以上轮次与网格对应关系为初始设计值，实现时可通过配置常量调整。

### 色差计算规则

- 基础颜色随机生成（HSL 色彩空间）。
- 不同色方块与基础颜色的色差（ΔE 或 ΔH + ΔS + ΔL 加权距离）随轮次递增而减小。
- 色差下限不低于人眼可辨识阈值，确保每一轮理论上均可被正确识别。

## 关键业务对象及字段

| 数据项 | 存储方式 | 说明 |
|--------|----------|------|
| 当前得分 | 页面内存 | 本局累计正确次数 |
| 最高分 | localStorage | 历史最高得分，前缀 `color-challenge-` |
| 当前轮次 | 页面内存 | 当前处于第几轮 |
| 最长存活轮数 | localStorage | 历史最长存活轮数 |
| 网格尺寸 | 页面内存 | 当前轮次的网格 N×N |
| 基础颜色 | 页面内存 | 当前轮的基础色值 |
| 不同色位置 | 页面内存 | 不同色方块的行列坐标 |

## 交互说明

- 进入游戏后自动生成第一轮方块，无需额外点击"开始"。
- 玩家点击方块即判定，正确时方块整体平滑过渡到下一轮（无闪烁），错误时显示结束弹层。
- 点击"再来一局"清空当前状态，重新从第 1 轮开始。
- 横竖屏切换时方块网格自动重新布局，保持方块为正方形且充满可用宽度。
- 触摸反馈：正确点击时方块短暂缩放或高亮；错误时网格整体抖动后弹出结束面板。

## 边界场景与异常

| 场景 | 处理方式 |
|------|----------|
| 极端色差导致无法辨识 | 色差计算设置合理下限，保证理论可辨识 |
| 快速连续点击 | 每轮只响应第一次点击，判定后禁用触摸直到下一轮就绪 |
| 后台切换回来 | 游戏状态保持，不重置 |
| 无障碍访问 | 方块不依赖颜色文字说明，但纯色觉游戏天然对色觉障碍用户不友好，可在页面底部添加提示文案 |

## 非功能要求

- 页面首屏加载 < 1s（纯静态资源，无外部依赖）。
- 方块渲染使用 CSS Grid + background-color，不依赖 Canvas，保证流畅性。
- 支持 iOS Safari 和 Android Chrome 最近两个主版本。
- 视口设置 `width=device-width, initial-scale=1.0, user-scalable=no`。

## 验收标准

> 以下标准为迁移时依据原文流程、边界与既有实现归纳补充。

1. 进入页面自动开始第 1 轮，无需点击"开始"。
2. 点击不同色方块得分 +1 并进入下一轮；点错展示结算弹层，含本局得分、存活轮数与历史最高记录。
3. 最高分与最长存活轮数按 `color-challenge-` 前缀持久化，刷新或重进后保留。
4. 「再来一局」清空当前状态，从第 1 轮重新开始。
5. 每轮只响应第一次点击；后台切换回来后游戏状态不重置。
