# 推箱子 · 核心玩法（REQ-SK001）

## 背景

平台解谜线缺"空间规划+步序优化"类玩法；推箱子是 sliding-puzzle（单滑块）之后更上层楼的多物体推移谜题，Undo 机制天然锻炼"走一步想三步"。关卡采用 David W. Skinner 的 Microban 新手关卡集（社区惯例免费使用、需署名），难度平缓爬坡、体量精小，适配 10-18 岁。

## 目标与范围

**本次覆盖**：
1. 经典推箱子：仓库管理员把所有箱子推到目标点；箱子只能推不能拉，一次一个。
2. 关卡集：Microban 精选 60 关，分三档（1-20 入门 / 21-40 进阶 / 41-60 挑战），关卡文本数据入库（`levels.js` 数据产物，文件头署名来源与许可惯例）。
3. 双端操控：PC 方向键 / WASD；移动端棋盘滑动手势 + 屏幕方向键（操作栏十字键）。
4. Undo 与重开：完整撤销栈（含推动），一键重开本关。
5. 计量与纪录：步数（人物移动数）与推数（推动箱子数）双计数；每关历史最少步数入档。
6. 解锁递进：过关解锁下一关，选关弹窗可回打已解锁关。
7. 胜利判定：所有箱子都位于目标点即过关（箱子在目标点上时显示合体态）。
8. 接入平台首页游戏目录（age: all，device: all）。
9. 死角温和提示：箱子被推入墙角（正交两方向均被墙堵、且不在目标点）后，该箱变暗红警示并在棋盘下方出现提示条，引导「撤销 / 重开」自救；提示非阻断，撤销或重开后随棋盘刷新自动消失。

**本次不覆盖**：关卡编辑器、自选皮肤、移动路线录制回放、更多关卡包（Microban II-IV）。

## 用户角色

- **青少年（10-18 岁）**：主要玩家，追求最少步数通关的优化乐趣。

## 页面清单

- **对局页**（单页游戏）：页头（游戏名 + 关卡档位胶囊）、计时板（步数/推数/本关最少步）、棋盘（墙/地板/目标点/箱子/人）、操作说明一行字、操作栏（方向十字键 + 撤销/重开/选关）、过关弹窗（步数/推数/最少步纪录 + 下一关）、选关弹窗。
- 平台首页卡片（注册项）。

## 核心业务流程

1. 进入页面：加载当前关卡（首次第 1 关），棋盘渲染墙、目标点、箱子与人。
2. 方向输入：人朝该方向移动；前方是箱子且箱子再前方为空地 → 人与箱子同移一格（推数 +1）；否则不动（无效输入无惩罚，轻微视觉反馈）。
3. 每次有效移动前压栈（人或箱旧坐标），Undo 弹栈还原，步数/推数回退。
4. 所有箱子位于目标点 → 过关弹窗（本关步数/推数、是否刷新最少步纪录）→ 下一关解锁。
5. 选关弹窗按三档分组展示已解锁关；刷新后解锁进度与最少步纪录保留。

## 关键业务对象及字段含义

- **关卡文本（level text）**：标准 Sokoban 文本格式——`#` 墙、`@` 人、`+` 人在目标点、`$` 箱、`*` 箱在目标点、`.` 目标点、空格 地板；由 `parseLevel` 解析为结构化对象。
- **关卡对象（level）**：`{ width, height, walls, goals, boxes, player }`（坐标集合/数组）。
- **步数（moves）/推数（pushes）**：人物有效移动计步，其中含推动的计推。
- **最少步纪录（best）**：每关历史最少步数。

## 权限与可见范围

无账号体系，仅本机存档；关卡数据来源署名在文件头与游戏页脚可见。

## 边界场景与异常

- **推箱入死角**：不阻止操作（宽松原则），但推入墙角后温和提示——死箱暗红高亮 + 提示条引导「撤销 / 重开」；玩家仍可自由走动。只做墙角判定（相邻两边为墙且不在目标点），不覆盖多箱互冻的复杂死锁（易误报且少见）。
- **滑动与页面滚动冲突**：棋盘上滑动用于转向，`touch-action` 控制，页面不滚动。
- **关卡数据损坏/缺失**：解析校验（箱数=目标数 ≥1、恰 1 个人）不过的关跳过并顺延，smoke 保证入库关卡全部合法。
- **本地存储不可用**：可完整游玩，仅不记进度与纪录。

## 非功能要求

- 棋盘 DOM/CSS Grid 渲染，格子触控目标充足；60 关全量随页加载（数据量小）。
- 技术形态与仓库现状一致：无框架、无构建、静态单页、UTF-8、中文注释，不新增第三方依赖。

## 验收标准

1. 平台首页出现「推箱子」卡片，可正常进入游玩。
2. 键盘/滑动/屏幕方向键均可控人推箱；推墙、推两连箱、拉箱均正确无效。
3. Undo 全链路还原步数/推数；重开恢复初始；箱子全到位判胜。
4. 60 关解析全部合法（smoke 断言箱数=目标数、恰 1 人）；三档分组正确。
5. 过关解锁与最少步纪录刷新后保留；选关仅开放已解锁关。
6. smoke test（node 直跑）通过，覆盖关卡解析合法性、移动/推动纯函数、undo 往返、胜判、存档读写、死角检测（入角检出/贴墙不误报/目标点豁免）。
7. 浏览器实测：推箱入角 → 死箱暗红 + 提示条出现；撤销一步 → 警示消失。

## 待确认项

- 无（Microban 为社区惯例可用关卡集，署名方式已在设计文档定稿）。
