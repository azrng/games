# 倒水谜题 · 核心玩法（REQ-WP001）

## 背景

平台缺少经典数学谜题类游戏。水壶倒水问题（water jug puzzle）规则一句话可讲清（几个容量不同的空杯，靠「装满 / 倒光 / 互倒」量出目标升数），纯点击交互天然适配移动端与电脑端，且每关天然带「最优解」概念，适合做星级与步数挑战。按同批新游戏（编程小机器人 REQ-CR001）的交付方式，以自包含目录落地。

## 目标与范围

**本次覆盖**：
1. 单页自包含游戏 `src/water-pour/`（无构建、无框架、无新增依赖），入口已在 `src/data/games.js` 注册（slug `water-pour`，双端同路径）。
2. 核心玩法：屏幕上 2-3 个竖向杯子（CSS 绘制，蓝色水位条动画显示当前水量/容量，杯口标注容量如「5L」），顶部横幅展示本关目标（如「量出 4L」）。任一杯子水量**恰好等于**目标即过关。
3. 交互：点选一个杯子（高亮）再点另一个杯子 → 前者向后者倒水（倒到后者满或前者空，水位过渡动画）；选中杯子后也可用两个动作按钮「🚰 装满」「🫗 倒光」；再点已选中杯子取消选中。无效动作（同杯、源空、目标已满）不消耗步数并给出文案提示。
4. 15 个手工内置经典关卡（见「关键业务对象」关卡表），难度按容量规模与组合复杂度递进；每关运行时用 BFS 从全 0 状态求最优步数并预校验有解，smoke 测试兜底再验。
5. 操作辅助：撤销上一步（无限次，步数一并退回）、重开本关、提示（每关 3 次：用 BFS 从当前局面算出最优下一步，高亮对应杯子与按钮并给出文案）。
6. 星级：步数 ≤最优 ★★★、≤最优+3 ★★、通关 ★。存档（localStorage，key 前缀 `water-pour-`）：`unlocked-level`（只增不减，封顶 15）、`stars-<level>`（保留最大）、`best-<level>`（保留最少步数）；提供关卡选择弹窗（未解锁关卡显示锁头）。
7. 过关 overlay：星星逐颗弹入动画 + 本关步数 / 最少步 / 历史最佳，可再玩一次或进下一关（最后一关改为打开关卡选择）。

**本次不覆盖**：音效、额外关卡包、自由倒水比例（保留「倒满为止」经典规则）、排行榜。

## 用户角色

- 休闲玩家：体验经典谜题，凭直觉试错通关。
- 挑战型玩家：以最少步数（★★★）为目标优化策略，借助「最少步」与「本关最佳」数据自我比较。
- 学生 / 家长：把倒水问题当作量与逻辑思维的启蒙小游戏。

## 页面清单

- 游戏页 `src/water-pour/index.html`：页头（标题 + 当前关卡）、状态栏（步数 / 最少步 / 本关最佳）、目标横幅、杯子区、状态文案、动作按钮区（装满 / 倒光）、操作按钮区（撤销 / 提示 / 重开本关、关卡选择）、过关弹窗、关卡选择弹窗。
- 逻辑 `src/water-pour/script.js`：关卡数据、纯函数运算与 BFS 求解（挂 `window.WaterApi`）、UI 渲染与交互。
- 样式 `src/water-pour/style.css`：自包含 CSS，`:root` 变量统一 `--wp-` 前缀，清新水色主题。
- 测试 `src/water-pour/smoke.test.js`：node 原生 assert + vm 沙箱。

## 核心流程

1. 进入游戏，从已解锁的最新一关继续（新玩家第 1 关），所有杯子初始为空。
2. 点杯子 A 选中（高亮）→ 点杯子 B：A 向 B 倒水，水位动画过渡；或选中后点「装满 / 倒光」。
3. 每次有效动作步数 +1；无效动作不消耗步数并提示原因。
4. 任一动作后若某杯水量恰好等于目标：锁定输入，水位动画播完弹出过关 overlay，按步数评星，写入存档并解锁下一关。
5. 未量出前可无限撤销（恢复到上一步的状态与步数）、重开本关、用提示获得最优下一步（消耗 1 次，每关共 3 次）。
6. 「关卡选择」弹窗可回跳任意已解锁关卡；刷新页面进度不丢（localStorage）。

## 关键业务对象

### 状态与动作

- 状态：各杯当前水量数组（如 `[2, 3]`），初始恒为全 0。
- 动作三选一：`fill i`（装满杯 i）、`empty i`（倒光杯 i）、`pour i→j`（i 倒给 j，转移量 = min(i 当前量, j 剩余容量)）。
- 过关判定：`任一杯水量 === 目标`（超过不算）。

### 星级与存档

| 项 | 规则 |
| --- | --- |
| ★★★ | 步数 ≤ BFS 最优步数 |
| ★★ | 步数 ≤ 最优 + 3 |
| ★ | 通关即得 |
| `water-pour-unlocked-level` | 只增不减，1~15 封顶 |
| `water-pour-stars-<level>` | 0~3，保留历史最大 |
| `water-pour-best-<level>` | 最少步数，保留历史最小，0 表示未通关 |

## 边界场景与异常

- 无效倒水（同杯、源杯为空、目标杯已满）：状态不变、不计步数，状态文案说明原因。
- 撤销栈为空时点撤销：按钮置灰不可点。
- 提示次数用尽：提示按钮置灰；上一条提示展示期间重复点击不叠加消耗。
- 提示求解：从任意合法局面出发目标恒可达（先倒光全部杯子即回到全 0，再按最优解走），BFS 无解分支仅为防御性兜底。
- 关卡参数越界（如关卡选择传入超范围值）：收敛到 1~15 再进关，`levelConfig` 对非法关次抛错。
- localStorage 不可用（隐私模式等）：静默退回内存兜底，本局游玩不受影响，进度不跨会话保留。
- 存档值被手工改坏（非数字 / 越界）：读取时按默认值兜底，不崩溃。

## 非功能要求

- 保持无构建、无后端、无新增第三方依赖；静态打开页面即可玩，桌面与移动端同一入口。
- 全部触控目标 ≥ 44px；交互零 `alert/confirm`；水位变化用 CSS 过渡动画呈现。
- 顶部内容避让左上角悬浮返回按钮（`padding-top ≥ 56px`）；`viewport` 含 `viewport-fit=cover, user-scalable=no`。
- 自包含样式（`--wp-` 前缀），不污染平台全局样式。
- smoke 测试 `node src/water-pour/smoke.test.js` 直接跑通，覆盖文件约定、15 关有解性、BFS 与暴力枚举对拍、纯函数边界、星级与存档规则。

## 验收标准

1. 打开游戏页显示 15 关中的当前关，杯子为空、目标横幅与「最少步」与关卡表一致。
2. 点选 → 点选完成一次倒水，水位动画过渡，步数 +1；装满 / 倒光按钮仅在有选中杯时可用。
3. 任一杯恰好量出目标即弹过关 overlay：星级符合步数规则，星星有弹入动画；存档三项均正确写入（星级保留最大、最佳保留最小、解锁只增不减）。
4. 撤销可无限次回退且步数同步退回；重开本关恢复全 0 与 3 次提示。
5. 提示消耗次数并正确高亮下一步涉及的杯子 / 按钮；每关最多 3 次。
6. 关卡选择弹窗：未解锁关卡不可进，已解锁关卡显示历史星级。
7. `node src/water-pour/smoke.test.js` 输出 `water pour smoke test passed`。
