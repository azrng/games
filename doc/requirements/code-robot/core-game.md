# 编程小机器人 · 核心玩法（REQ-CR001）

## 背景

平台缺少编程启蒙类游戏。面向儿童的方向指令游戏（参考 Blockly maze 类关卡的关卡组织方式，代码全部原创）能让玩家在"编排指令 → 运行 → 观察结果 → 修正程序"的循环中建立顺序、转向、路径规划等编程基础概念，且纯点击交互天然适合移动端与电脑端。

## 目标与范围

**本次覆盖**：
1. 单页自包含游戏 `src/code-robot/`（无构建、无框架、无新增依赖），入口已在 `src/data/games.js` 注册（slug `code-robot`）。
2. 棋盘玩法：正方形网格上，机器人从起点（带朝向）出发，玩家点击指令块（⬆️前进 / ↰左转 / ↱右转）追加到「程序序列」，点「运行」逐步执行；撞墙或出界则冒烟失败并终止程序，集齐宝石后走到终点即过关。
3. 12 个手工内置关卡递进：第 1-3 关直线与简单转弯（无墙无宝石）、4-6 关加墙与连续转向、7-9 关加 1-2 颗宝石（必须全部收集后到达终点才算过关）、10-12 关 7×7 多墙多宝石复杂路径；棋盘尺寸 1-4 关 5×5、5-8 关 6×6、9-12 关 7×7。
4. 每关附 par 步数与参考解法（referenceProgram）：星级按使用指令数评定——≤par ★★★、≤par+2 ★★、过关 ★；程序长度上限 = par + 4。
5. 存档（localStorage，key 前缀 `code-robot-`）：unlocked-level（只增不减）、stars-\<level\>（保留最大值）；提供关卡选择弹窗、重开按钮、清空程序按钮、运行中停止按钮、演示按钮（载入参考解法并自动运行）。

**本次不覆盖**：音效、关卡编辑器、更多关卡包、拖拽式指令排序（当前为点击追加 + 点小卡删除）。

## 用户角色

- 儿童玩家：通过大按钮与即时动画反馈学习"程序 = 指令序列"的概念。
- 家长/教师：可用演示按钮展示参考解法，用 par 步数引导孩子优化程序。

## 页面清单

- 游戏页 `src/code-robot/index.html`：页头（标题 + 当前关卡）、状态栏（指令数 / Par 步数 / 最佳星级）、棋盘、程序序列条、指令块按钮区、操作按钮区、过关弹窗、关卡选择弹窗。
- 逻辑 `src/code-robot/script.js`：关卡数据、纯函数模拟器（挂 `window.RobotApi`）、UI 渲染与运行循环。
- 样式 `src/code-robot/style.css`：自包含 CSS，`:root` 变量统一 `--cr-` 前缀。
- 测试 `src/code-robot/smoke.test.js`：node 原生 assert + vm 沙箱。

## 核心流程

1. 进入游戏 → 自动载入已解锁的最新关卡（新玩家为第 1 关），机器人停在起点并显示朝向箭头。
2. 点击指令块 → 指令追加到程序序列（小卡展示，点小卡删除该条，超过 par+4 条后拒绝追加并提示）。
3. 点「运行」→ 机器人按序列逐步执行（每步约 400ms 动画，移动 + 朝向箭头旋转），当前执行的小卡高亮。
4. 执行中撞墙 / 出界 → 💥 冒烟动画 + 失败提示，程序终止，可继续编辑后重新运行；点「停止」可随时中断。
5. 集齐全部宝石且走到终点 → 过关弹窗展示星级、使用指令数、宝石数；保存星级并解锁下一关。
6. 宝石未集齐时到达终点：机器人停在终点但不判过关，提示先去收集宝石。

## 关键业务对象

### 关卡数据

内置于 `script.js` 的 `LEVELS`，用字符画网格表示：`#` 墙、`.` 空地、`S` 起点、`G` 终点、`*` 宝石，外加起始朝向（U/D/L/R）与 par 步数。`parseLevel(level)` 解析为 `{ size, walls, start, facing, goal, gems, par }`。

### 模拟结果

`simulateProgram(level, program)` 纯函数返回 `{ ok, steps, gemsCollected, crashAt }`：`ok` 仅在"到达终点且宝石集齐"时为 true；`crashAt` 为撞墙/出界指令的序号（1 起），0 表示未撞击；程序超长按 par+4 截断。

### 星级与存档

| 对象 | 规则 |
| --- | --- |
| 星级 | steps ≤ par → 3 星；≤ par+2 → 2 星；过关其余 → 1 星；未过关无星 |
| `code-robot-unlocked-level` | 过关后 +1，只增不减，上限 12 |
| `code-robot-stars-<level>` | 0-3，只保留历史最大值 |

## 边界场景与异常

- 程序为空点「运行」：按钮禁用，不执行。
- 程序超过 par+4：拒绝追加并提示先删除。
- 撞墙 / 出界：程序立即中断，播放冒烟动画，给出第几条指令出错的提示。
- 程序执行完毕但未到终点（或宝石未集齐）：提示失败原因，机器人停留原地，可重编。
- 运行中点「停止」：立即中断，程序保留可继续编辑；再次运行时机器人从起点重新出发。
- 关卡选择弹窗：未解锁关卡显示 🔒 且禁用；已解锁关卡显示历史最佳星级。
- localStorage 不可用（隐私模式等）：降级为内存存档，不影响单次游戏。

## 非功能要求

- 保持无构建、无后端、无新增第三方依赖；静态打开即可玩。
- 触控目标 ≥44px；交互零 alert/confirm，全部用页面内提示与弹窗。
- 自包含 CSS（`--cr-` 前缀变量），儿童向明亮配色；顶部内容避让左上角悬浮返回按钮。
- 代码风格与既有游戏一致（IIFE + 'use strict'，纯函数挂 `window.RobotApi` 供测试）。

## 验收标准

1. 12 关全部可用各自 referenceProgram 以恰好 par 步通关且宝石集齐（smoke 测试覆盖）。
2. 棋盘尺寸与关卡梯度一致：1-4 关 5×5、5-8 关 6×6、9-12 关 7×7；1-3 关无墙无宝石、4-6 关有墙、7-9 关 1-2 颗宝石、10-12 关 ≥2 颗宝石。
3. `simulateProgram` 对撞墙、出界、宝石未集齐、程序超长截断、过关即提前结束五种边界行为正确。
4. 星级边界正确：par/par+2/par+3 分别得 3/2/1 星；unlocked 只增不减、stars 保留最大值。
5. `node src/code-robot/smoke.test.js` 直接跑通并输出 `code robot smoke test passed`。
6. 页面包含 viewport-fit=cover、user-scalable=no、`../js/game-back.js` 挂载；运行中「停止」可中断；指令块、小卡、按钮触控目标 ≥44px。
