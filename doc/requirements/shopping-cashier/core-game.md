# 购物小掌柜 · 核心玩法（REQ-SP001）

## 背景

游戏平台已收录多款儿童向启蒙游戏（点灯、时钟认知、数学小勇士等），但缺少人民币认知与货币换算类玩法。「认识面额、凑钱付款、计算找零」是低年级数学与生活启蒙的高频场景，适合做成纯点击交互的移动端小游戏。新增「购物小掌柜」：玩家扮演收银员，通过为顾客凑钱付款与找零，练习面额组合与减法心算。

## 目标与范围

**本次覆盖**：
1. 12 关、每关 5 单的收银闯关玩法：凑整付款（第 1-8 关）与找零模式（第 9-12 关），档位递进见「关键业务对象」。
2. 人民币面额按钮 1/5/10/20/50/100 元：1 元为银色圆形硬币样式，其余为 CSS 绘制、真实感配色但卡通化的纸币色块；未开放面额置灰不可点。
3. 付款台：累计金额实时显示、按面额展示已放张数，点付款台内某面额撤回一张，支持一键清空。
4. 付账校验：恰好等于应付金额即成功（成功动画后进入下一单）；金额不对时给出儿童友好差额提示（「多了 2 元」「还差 3 元」），不算失败、可继续调整，首次付对前的错误付账次数计入星级。
5. 商品池不少于 24 种 emoji 商品（emoji + 名称 + 常见单价区间），所有价格均为整数元。
6. 星级（每关失误 0 次 ★★★、≤2 次 ★★、其余 ★）、存档（`shopping-cashier-unlocked-level`、`shopping-cashier-stars-<level>`）、关卡选择弹窗与重开本关按钮。

**本次不覆盖**：音效配音、多语言、商品池后台配置、真实货币图片素材、家长监控报表。

## 用户角色

- 儿童玩家（主要）：6-9 岁，已认识数字与 20 以内加减法，通过游戏认识人民币面额并练习组合付款。
- 家长/教师：陪同游玩，讲解面额与找零概念；依赖星级了解孩子掌握程度。

## 页面清单

- 游戏页 `src/shopping-cashier/index.html`（自包含，移动端优先，双端可玩）
- 样式 `src/shopping-cashier/style.css`（自包含 CSS，`:root` 变量统一 `--sc-` 前缀）
- 逻辑 `src/shopping-cashier/script.js`（挂 `window.CashierApi`，纯函数可测）
- 测试 `src/shopping-cashier/smoke.test.js`（node 原生 assert + vm 沙箱）
- 文档 `doc/requirements|design/shopping-cashier/core-game.md`
- 平台目录 `src/data/games.js`：slug `shopping-cashier` 已注册（本任务只做断言，不修改）

## 核心流程

1. 进入页面 → 从最高已解锁关开始，展示当前订单：顾客头像、商品（emoji 大图标 + 名称 + 价签「N元」）。
2. 点面额按钮把钱放入付款台，累计金额与各面额张数实时刷新；点付款台内某面额撤回一张，或清空重来。
3. 点「付账」：恰好等于应付 → 成功动画 → 弹窗「算对了」→ 下一单；金额不对 → 失误 +1 并提示差额，可继续调整后再付。
4. 找零模式（第 9-12 关）：题面提示「应收 X 元，顾客付了 Y 元」，玩家心算找零 Z=Y-X，从开放面额凑出恰好 Z 元（页面不直接给出 Z）。
5. 第 5 单完成 → 结算弹窗：按本关失误次数给星级并写档，解锁下一关。
6. 关卡选择弹窗可回到任意已解锁关卡；「重开」按钮重置本关进度。

## 关键业务对象

### 关卡档位

| 关卡 | 模式 | 价格值域（整数元） | 顾客支付 | 开放面额（元） |
| --- | --- | --- | --- | --- |
| 1-4 | 凑整付款 | 1-10（下限随关卡通升，上限恒 10） | —— | 1、5 |
| 5-8 | 凑整付款 | 6-50（下限随关卡通升，上限恒 50） | —— | 1、5、10、20、50 |
| 9-10 | 找零 | 3-20 | 固定 50 | 1、5、10、20 |
| 11-12 | 找零 | 21-99（上限取 99 而非 100，保证找零 ≥ 1 元） | 固定 100 | 1、5、10、20、50 |

找零可表示性：1 元面额恒开放，任意整数元找零均可由开放面额组合出；生成侧以贪心拆分作为可表示性校验兜底。

### 订单与付款台

- 订单 `{ item, price, paid? }`：`item` 含 emoji 与名称；凑整档无 `paid`，找零档 `paid` 为顾客支付整钱。
- 付款台：面额数组（可重复），累计金额与张数实时汇总。
- 星级：`starRating(mistakes)`，按每关累计失误次数 0 / ≤2 / ≥3 → 3 / 2 / 1 星。
- 存档：`shopping-cashier-unlocked-level`（只增不减）、`shopping-cashier-stars-<level>`（保留历史最高星级）。

## 边界场景与异常

- localStorage 不可用（隐私模式、测试环境）：退化为内存兜底存档，游戏可玩、进度不持久、不报错。
- 付款台为空时点「付账」：仅给轻提示、不计失误。
- 找零为 0 元的退化订单不会生成（第 11-12 关价格上限 99 元保证 Z ≥ 1）。
- 未开放面额按钮始终置灰，点按无效；已解锁关卡数只增不减，星级只保留最高。
- 12 关全部通关后，结算弹窗「下一关」按钮文案变为「从头再玩」。
- 移动端小屏：面额按钮与付款台标签可换行，触控目标均 ≥ 44px，无横向溢出。

## 非功能要求

- 纯静态、无构建、无框架、无新增依赖/CDN；静态打开即可玩。
- 全部文件 UTF-8，注释一律中文；JS 使用 ES6+，禁 `var`/`eval`/宽松相等；交互禁 `alert`/`confirm`。
- 移动端适配：`viewport-fit=cover, user-scalable=no`，顶部内容避让悬浮返回按钮（header 区 padding-top ≥ 56px）。
- 儿童向明亮配色；游戏逻辑与 UI 分层，`window.CashierApi` 纯函数可被 node + vm 沙箱直接测试。

## 验收标准

1. `node src/shopping-cashier/smoke.test.js` 直接跑通，输出 `shopping cashier smoke test passed`。
2. `generateOrder` 同种子完全可复现；12 关价格均在档位值域内且为整数；找零档找零 Z 可由开放面额组合出且 Z ≥ 1。
3. `evaluatePayment` 对恰好/多了/还差三种情况判定正确且差额数值正确；`computeChange` 结果正确。
4. 星级边界（0/1/2/3 次）与关卡档位递进断言通过；存档 unlocked 只增不减、stars 保留最大值。
5. `index.html` 含 `viewport-fit=cover`、`user-scalable=no`，`</body>` 前按序引入 `script.js` 与 `../js/game-back.js`，标题为「购物小掌柜 - 游戏平台」。
6. `src/data/games.js` 中存在 `slug: "shopping-cashier"` 与 `mobilePath: "src/shopping-cashier/index.html"`。
