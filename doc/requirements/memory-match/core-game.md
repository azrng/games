# 记忆翻牌 · 核心玩法（REQ-MM001）

## 背景

平台儿童向游戏缺少经典的「记忆配对」益智玩法。`src/data/games.js` 已注册 `memory-match` 条目（移动端路径 `src/memory-match/index.html`，儿童向、双端可玩），需要按仓库「纯静态、无构建、自包含」的约定补齐游戏本体实现。

## 目标与范围

**本次覆盖**：
1. 12 关卡阵递进的翻牌配对玩法：卡背朝上网格，CSS 3D 翻转动画（卡背为纯色渐变 + 圆点花纹），点两张翻开——同款保持正面并轻微弹跳、绿色高亮配对；不同展示约 800ms 后翻回，期间锁定点击防连点。
2. 主题池按关轮换：动物 / 水果 / 交通 / 食物 / 海洋共 5 组主题，每组 ≥18 个不同 emoji（覆盖最大关卡 18 对的需求）。
3. 星级规则（翻两张记 1 次：≤对数×2 三星、≤对数×2.5 两星、其余一星）与存档（键前缀 `memory-match-`：解锁进度、每关星级、每关最少翻牌次数）。
4. 关卡选择弹窗（未解锁禁用）、重开本关按钮、过关结算弹窗（星星弹出动画）。
5. 首次进入的玩法说明提示条（页面内横幅，可关闭，关闭状态记入存档）。

**本次不覆盖**：首页入口与目录数据调整（`src/data/games.js` 已注册，不改）、平台级组件、其他游戏。

## 用户角色

- 3-8 岁儿童：以触屏点选为主，需要大触控目标、明亮配色、直观的对错反馈（配对成功弹跳高亮 / 失败短暂展示后翻回）。
- 家长 / 成人：通过关卡选择弹窗与星级了解孩子进度；「本关最佳」记录最少翻牌次数，可引导孩子挑战更少步数。

## 页面清单

- `src/memory-match/index.html`（唯一页面，自包含）
- `src/memory-match/style.css`（自包含样式，`:root` 变量以 `--mm-` 为前缀）
- `src/memory-match/script.js`（游戏逻辑，纯函数挂 `window.MemoryApi` 供测试）
- `src/memory-match/smoke.test.js`（node 原生 smoke 测试）
- `src/data/games.js`（已注册条目，本次不改）

## 核心业务流程

1. 首次进入：页头下方出现玩法说明提示条（「每次翻开两张卡，图案相同就配对成功；全部配对即过关，翻牌次数越少星级越高」），点「知道了」关闭后永久不再出现。
2. 进入页面自动进入最新解锁关（无存档从第 1 关开始），按关卡生成对应主题与卡阵。
3. 点卡翻开：第 1 张保持翻开等待；第 2 张翻开即计 1 次翻牌——
   - 同款：两张保持正面，轻微弹跳 + 绿色高亮，计入已配对数；
   - 不同：两张正面展示约 800ms 后自动翻回，期间锁定点击。
4. 全部配对成功：弹出结算弹窗，星星依次弹出动画展示星级；保存历史最高星级与本关最少翻牌次数，解锁下一关；第 12 关通关后不再出现「下一关」。
5. 「关卡选择」可随时切换到任意已解锁关卡（未解锁显示 🔒 禁用）；「重开本关」重置当前关翻牌次数与配对进度。

## 关键业务对象

1. 卡牌 `{ emoji, pairId }`：`emoji` 为卡面图案，`pairId` 为配对编号（同款相等）；牌阵由 `buildDeck(themeKey, pairs, seed)` 生成，长度恒为 2×pairs，每对恰 2 张，Fisher-Yates 种子洗牌保证同种子可复现。
2. 主题池（按关轮换，每组 ≥18 个不同 emoji）：

| 主题 | key | emoji 数量 |
| --- | --- | --- |
| 动物 | `animals` | 19 |
| 水果 | `fruits` | 21 |
| 交通 | `transport` | 20 |
| 食物 | `foods` | 21 |
| 海洋 | `ocean` | 18 |

3. 关卡卡阵递进表（12 关，移动端窄屏仅视觉降列、数据不变）：

| 关卡 | 对数 | 阵型（列×行） |
| --- | --- | --- |
| 1-2 | 6 | 3×4 |
| 3-4 | 8 | 4×4 |
| 5-6 | 10 | 4×5 |
| 7-8 | 12 | 4×6 |
| 9-10 | 15 | 5×6 |
| 11-12 | 18 | 6×6 |

4. 星级：`starRating(flips, pairs)`，翻两张记 1 次——`flips ≤ pairs×2` 三星（零失误完美）、`flips ≤ pairs×2.5` 两星、其余一星。
5. 存档（localStorage，键前缀 `memory-match-`）：`memory-match-unlocked-level`（只增不减）、`memory-match-stars-<level>`（保留历史最大值）、`memory-match-best-<level>`（保留历史最少翻牌次数）、`memory-match-tip-dismissed`（玩法提示条关闭标记）；存储不可用时内存兜底。

## 边界场景与异常

- localStorage 不可用（隐私模式等）：读写静默降级到内存，本局可玩、不报错；不做跨会话存档承诺。
- 连点 / 重复点击：已翻开、已配对或判定锁定期间的卡一律忽略点击，防止误判与穿帮。
- 第 12 关通关：结算弹窗不再出现「下一关」按钮。
- 越界关卡号（小于 1 或大于 12）：按边界关卡（1 / 12）兜底。
- 牌阵请求对数超出主题池：按主题池上限收敛；退化请求（0 / 非法值）按 1 对兜底。
- 移动端窄屏：6 列卡阵在 ≤480px 降为 4 列、≤350px 降为 3 列（CSS 断点，数据不变）；卡牌触控目标 ≥44px。

## 非功能要求

- 纯静态、无构建、无新增第三方依赖；静态打开页面即可玩。
- `<meta viewport>` 含 `viewport-fit=cover, user-scalable=no`；顶部内容避让左上角悬浮返回按钮（移动端页头顶部留白 ≥56px）。
- 儿童向明亮配色，样式自包含（`--mm-*` 变量），卡背不依赖图片；`prefers-reduced-motion` 下关闭翻转过渡与装饰动画。
- 同种子牌阵完全可复现（种子随机）；`node src/memory-match/smoke.test.js` 直接跑通。

## 验收标准

1. 共 12 关，卡阵与递进表逐关一致（6/8/10/12/15/18 对，3/4/4/4/5/6 列，行数 = 卡数 ÷ 列数）；主题按关轮换覆盖全部 5 组主题。
2. `buildDeck` 返回长度 2×pairs 的牌阵，每个 pairId 恰 2 张，同种子复现、不同种子多数分布不同，卡面 emoji 无重复配对。
3. 星级边界：≤pairs×2 → 3 星、≤pairs×2.5 → 2 星、其余 → 1 星；解锁进度只增不减；星级保留最大值、最佳保留最少翻牌次数；所有存储键以 `memory-match-` 为前缀。
4. 页面含 `viewport-fit=cover`、`user-scalable=no`，按顺序挂载 `script.js` 与 `../js/game-back.js`，标题为「记忆翻牌 - 游戏平台」。
5. `node src/memory-match/smoke.test.js` 通过并输出 `memory match smoke test passed`。
