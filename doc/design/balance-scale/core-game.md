# 天平称重 · 核心玩法设计（DES-BS001）

## 需求追溯

- 关联 REQ-BS001，覆盖其全部「本次覆盖」范围（12 关四档位、SVG 天平题面、数值选项作答、首答星级与存档、关卡选择与重开）。
- 无裁剪项；档位表、星级规则直接取自 REQ-BS001「关键业务对象」，落地以 `src/balance-scale/script.js` 为准。

## 技术设计

### 模块职责与数据流

```text
questionSeed(level, i) ─▶ generateEquation(level, seed) ─▶ state.question
   renderScales（SVG 天平 ×N，水果坐标 panFruitSpots） ─▶ questionText + renderOptions(generateOptions(answer, seed))
   点选选项 ─▶ settleAnswer（首答计数 / 答错抖动 / ✅动效） ─▶ 4 题完成 ─▶ starRating
        └▶ saveStars / saveUnlockedLevel ─▶ 结算 overlay
solveEquation（代换法，有理数精确运算）：档位四生成时定答案 + 测试独立复核共用同一实现
```

- `script.js`：IIFE + `'use strict'`，逻辑与纯函数同文件，`window.BalanceApi` 暴露纯函数供 smoke 测试（vm 沙箱 + Map 桩 localStorage）。
- `index.html`：静态骨架含 `scales-area` 容器，天平 SVG 由 JS 构建；`style.css` 自包含 `--bs-*` 主题。

### 纯函数 API（window.BalanceApi）

| 函数 | 说明 |
| --- | --- |
| `generateEquation(level, seed)` | 返回 `{ equations: [{left, right}...], question: {target, unit}, answer }`；等式两侧为水果键数组（重复表示数量），按档位构建推导链，answer 恒为正整数 ≤30 |
| `solveEquation(equations, target, unit)` | 代换法：以 unit=1 反复解「只含一个未知水果」的等式，全部解出后回代校验等式平衡；欠定、非正整数或矛盾返回 null |
| `generateOptions(answer, seed)` | 4 个互异非负整数选项含正确项：answer±1/±2/±3 过滤负数去重后随机抽 3 个，不足时向后补齐，Fisher-Yates 洗牌 |
| `starRating(correct, total)` | 全对 3 星、≥75% 2 星、其余 1 星（4 题即 4/≥3/其余） |
| `levelConfig(level)` / `levelCount()` | 档位与该关单段倍数上限（`LEVEL_MULTIPLIER_MAX` 逐关放宽）；共 12 关 |
| `questionSeed(level, index)` | `BASE_SEED + level×3571 + index×97` |
| `formatEquation(eq)` | 等式的 emoji 文案（如 `🍎 = 🍋🍋`），同组重复计数、组和之间用 `+`，兼作 SVG aria-label |
| 存档函数 | `loadUnlockedLevel/saveUnlockedLevel/loadStars/saveStars`；unlocked 只增不减、stars 保留最大值；try/catch + 内存对象兜底 |

### 关键技术决策

1. **生成器按「推导链」构造而非随机方程**：柠檬固定为链底（值 1），每段等式引入一个新水果 = k×已知水果（档位四的 🍇=🍌+c🍋 是「两个已知量之和」的特例），联立天然恰有唯一解、无循环引用；档位四的 answer 直接由 `solveEquation` 解出，生成与复核同口径。
2. **「只出整除题」由链结构保证**：链上每个水果的值都是倍数乘积，只有 unit 在链中位于 target 之下（或反向等式把柠檬放重侧）时 answer 才是整数；生成器只在这些 (target, unit) 对里选提问方向，天然不产生分数题。
3. **`solveEquation` 用 `{num, den}` 有理数而非浮点**：反向推导会产生分数中间值（如 1/2），`den !== 1` 即精确识别为非整数解并返回 null，不依赖浮点容差。
4. **天平用 SVG 构建**：横梁/吊绳/托盘/支架几何固定（viewBox 320×150，吊挂点 x=40/280、托盘口 y=112），水果用 `<text>` emoji 摆放（≤3 个一行、4~6 个两行下多上少），数量与等式严格一致；横梁恒水平表达平衡，加载时轻微摆动动画（`bsBalance`）增强「天平」观感；托盘为椭圆弧 path（`A 32 26 0 0 0` 向下鼓出）。
5. **多台天平纵向堆叠而非并排**：两台并排时 emoji 随 viewBox 缩放过小（<12px），堆叠全宽最清晰；三元链三台时收窄单台宽度（`is-trio`）控制整页高度。
6. **答对后 950ms 自动跳题的计时器可取消**：`startLevel` 先 `clearAdvanceTimer()`，儿童在动画期间快速点「重开本关 / 下一关」不会把上一关的跳题定时器串进新一关（对参考实现的小改进）。
7. **存档兜底**：所有 localStorage 读写包 try/catch，失败落到模块内内存对象；`loadUnlockedLevel` 收敛到 `[1, 12]`。

## 界面原型

单天平主界面（tier 1 · 默认态）：

```text
┌──────────────────────────────┐
│ [返回]  BALANCE SCALE         │
│         天平称重    〔第 1 关〕│
│ ┌───────────┐ ┌───────────┐ │
│ │题目  1 / 4│ │首答正确 0 题│ │
│ └───────────┘ └───────────┘ │
│      〔单天平 · 直接倍数〕      │
│   ┌────────────────────────┐ │
│   │  ════════════════════   │ │  ← 横梁水平 = 平衡
│   │   🍎    ▲    🍋🍋🍋      │ │     中央支架 ▲ + 「=」徽标
│   │  (托盘)        (托盘)     │ │  ← 托盘数量与等式一致
│   │     🍎 = 🍋🍋🍋           │ │  ← emoji 等式文案
│   └────────────────────────┘ │
│     1 个🍎 = 几个🍋 ？          │
│   ┌─────────┐  ┌─────────┐  │
│   │    2    │  │    3    │  │
│   ├─────────┤  ├─────────┤  │
│   │    4    │  │    5    │  │
│   └─────────┘  └─────────┘  │
│   答对 → ✅+⭐动效 / 答错 →      │
│   选项抖动 +「再试一次」          │
│  〔重开本关〕  〔关卡选择〕       │
└──────────────────────────────┘
```

双天平组合态（tier 2/3 · 两台堆叠）与三元链态（tier 4 · 三台收窄）：

```text
│   ┌────────────────────────┐ │
│   │ 🍌  =  🍎🍎             │ │  ← 第一台：🍌=🍎🍎
│   └────────────────────────┘ │
│   ┌────────────────────────┐ │
│   │ 🍎  =  🍋🍋             │ │  ← 第二台：🍎=🍋🍋
│   └────────────────────────┘ │
│      1 个🍌 = 几个🍋 ？         │  ← 两步推导 ⇒ 4
```

结算弹窗（overlay，星级 / 首答正确数 / 下一关可见性）：

```text
┌──────────────────────────────┐
│  （半透明遮罩 + 底部弹卡）        │
│  ┌──────────────────────────┐ │
│  │       LEVEL CLEAR         │ │
│  │       称重完成！            │ │
│  │        ★ ★ ☆              │ │   ← starRating(3, 4) = 2 星
│  │  ┌────────────────────┐  │ │
│  │  │ 首答正确     3 / 4   │  │ │
│  │  └────────────────────┘  │ │
│  │ 〔再玩一次〕  〔下一关〕     │ │   ← 第 12 关完成时隐藏「下一关」
│  └──────────────────────────┘ │
└──────────────────────────────┘
```

状态说明：无 loading 态（纯静态同步渲染）；错误态仅一种轻反馈——答错选项抖动 + 提示文案，不锁死流程、不显示答案；关卡选择弹窗中未解锁关卡置灰（「未解锁」文案）。

## 交互与异常

### 操作流程

1. 加载 → `startLevel(loadUnlockedLevel())`：按种子渲染天平、提问与 4 选项。
2. 点选项 → 对/错反馈：答对播放 ✅+星星动效，950ms 后自动进入下一题；答错该按钮抖动并提示，可重选。
3. 第 4 题答对 → 结算弹窗（星级、存档、解锁）；弹窗按钮或底部「重开本关 / 关卡选择」继续。
4. 关卡选择弹窗：12 关宫格，未解锁置灰，已解锁显示 `★☆☆` 历史星级，当前关高亮。

### 边界表

| 场景 | 处理 |
| --- | --- |
| localStorage 不可用 / 取值非法 | try/catch + 内存兜底；非法读值回落默认（解锁 1 关、0 星） |
| 答对动画期间点「重开本关 / 切换关卡」 | `startLevel` 先取消跳题计时器，不串题 |
| 第 12 关完成 | `saveUnlockedLevel` 收敛到 12，结算弹窗隐藏「下一关」 |
| answer=1 的选项生成 | 候补池 0/2/3/4 恰好补齐 3 个干扰项，全部非负互异 |
| 等式组欠定 / 含分数解（防御） | `solveEquation` 返回 null，生成器链式结构保证不会触发 |
| 托盘水果超过 6 个（防御） | emoji 等式文案折叠为 `🍋×n`（当前题库单托盘最多 5 个，不会触发） |

### 验证方式

1. smoke 测试（`node src/balance-scale/smoke.test.js`，node + vm + assert，localStorage 用 Map 桩）：
   - 场景 A（文件与目录约定）：viewport/标题/脚本顺序/返回脚本、`--bs-` 前缀、返回按钮避让样式、`games.js` 目录注册断言。
   - 场景 B（生成与求解）：12 关 × 8 种子下天平数与档位一致、answer 为正整数 ≤30 且与 `solveEquation` 独立推导一致、4 选项互异含正确项且非负、同种子可复现。
   - 场景 C（手算样例与边界）：单条/反向/两步/三元链样例、欠定与非整数返回 null、answer=1 等边界选项仍非负互异。
   - 场景 D（星级与存档）：星级边界 4/3/2/0、档位递进、unlocked 只增不减、stars 保留最大值、全新进度默认值。
2. 浏览器手工 smoke：天平托盘数量与等式一致且横梁水平、档位角标随关变化、答对 ✅ 动效、答错抖动可重选、关卡选择/重开/结算弹窗流转、390px 视口布局与返回按钮避让。
