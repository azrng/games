## 技术设计

### 模块与文件职责

```text
src/pinyin-typing/
├── index.html      # 三层 overlay：#menu（选档）/ #play（对局）/ #result（结算），自包含页面
├── style.css       # 全部视觉与动画，主题色用 CSS 变量定义
├── wordbank.js     # 纯数据：三档字库（1081 条），由 build-wordbank.js 生成，勿手改
├── build-wordbank.js  # 字库生成管道：拉取部编版课本数据 + 带调拼音表 → 生成 wordbank.js（node 直跑）
├── script.js       # 状态机、判键、TTS、存储、键位图与槽位渲染
└── smoke.test.js   # node + vm 桩测试（仿 typing-cannon 的自动桩方案）
```

依赖边界：不引入任何第三方库；语音用 `window.speechSynthesis`（浏览器内置）；持久化用 `localStorage`（键名见 CON-PT001）；平台接入仅两处——`src/data/games.js` 注册条目 + 引入 `src/js/game-back.js` 共享返回按钮。游戏页沿用仓库游戏自包含风格（不引 Bootstrap），以仓库现有游戏实现为准。

### 数据流向与状态变化

```text
MENU ──选档(tier)──▶ PLAY ──8 字完成──▶ RESULT ──┬─ 再来一局 ─▶ PLAY（同档重取字）
                      │                          └─ 回选档 ───▶ MENU
                      └─ Esc / 返回 ──▶ MENU（无惩罚）

PLAY 对局态：{ tier, queue[8], qi(当前第几字), slotIdx(槽位), wrongCount, combo, bestCombo }
  keydown(字母) ─ 命中 p[slotIdx] ─▶ slotIdx++ ; slotIdx===p.length ─▶ 字完成：
      星级 = wrongCount===0 ? 3 : wrongCount<=2 ? 2 : 1
      save.stars[tier][字] = max(旧值, 星级)；save.bestCombo[tier] = max(旧值, bestCombo)；persist()
      庆祝动画 ─▶ qi++ → 下一字 或 → RESULT
              ─ 未命中 ─▶ wrongCount++、combo=0、shake 动画（无其他状态变化）
```

- **取字算法**：`pool = 档内 stars 无记录的字` 洗牌取前 8；不足 8 用已掌握字洗牌补齐；挑战档词条含双字词（拼音为两音节连接串，槽位逻辑不变）。
- **TTS**：字出现时自动朗读「{汉字}，{拼音}，{示例词}」（rate 0.8）；点卡片重听；声音开关写 `save.muted` 持久化；任何 TTS 异常 try/catch 静默。
- **键位图**：26 字母 QWERTY 三行常驻，`slotIdx` 对应字母持续高亮闪烁；按错时该键闪红一次。

### 关键技术决策

1. **DOM 卡片而非 canvas**：玩法是静态卡片 + 槽位点亮，DOM + CSS 动画足够且可靠；canvas 只在单词大炮那种掉落射击场景才必要。
2. **keydown 而非 input 事件**：直接拿物理键字母，绕开中文输入法 composition 干扰；选档页的「切英文输入法」提示只是兜底文案，不做检测。
3. **贴纸由星级派生**：`stars[tier][字] ≥ 1` 即点亮，不存第二份贴纸列表，杜绝双写不一致。
4. **字库由生成管道对齐部编版课本（T044）**：`build-wordbank.js` 运行时拉取课本生字数据与带调拼音表（来源 github.com/cjp1016/hanzi-park，字表为课程事实内容），归一化数据源噪点（拉丁变体 g U+0261、数字标调 diu1），过滤不宜字与含 ü 音节（绿/旅类无键盘对应），多音字读音用小覆盖表按教学读音校准（如 谁→shéi）；三档=课本册次（一上 211 / 一下新增 287 / 二年级新增 563+双字词 20），档内保留课本顺序。精选条的插图与例词在重生成时原样保留。
5. **插图/例词可空降级**：扩量字 e=""、w=""，卡片隐藏图位、信息行只显示带调拼音，TTS 只朗读汉字本身；精选字（现 97 条）的配图与例词随人工补充逐步覆盖。
6. **字库与逻辑分离**：wordbank.js 纯数据，加字改档不碰逻辑；smoke 对数据做静态断言（拼音合法性、无 v/ü、档内汉字唯一、档位数量）。
7. **零失败状态机**：wrongCount 只影响星级与动画，没有生命值/失败/终止分支，状态机面小、测试面小。

## 交互与异常

- **按键流程**：keydown（仅 a-z，大小写均收）→ 命中：点亮槽位 + 轻快反馈 + 高亮右移；未命中：卡片 shake + 该键闪红 + wrongCount++（无扣减、无打断）。
- **字完成**：约 800ms 庆祝后自动进下一字，保持心流，无需点击。
- **退出**：Esc 回选档（对局零损失故不加确认弹窗）；左上角 game-back 返回平台首页。
- **TTS 异常/无中文语音**：静默跳过，重听入口保留；不弹错误。
- **存储异常**：读写全部 try/catch；读取损坏重置默认值；隐私模式首次提示一次「进度将不会保存」。
- **刷新**：启动 load() 恢复菜单进度数字；对局中刷新回到选档页（对局态不持久化，符合零损失原则）。
- **验证方式**：手工 smoke（选档 → 对局 → 故意按错 → 完成 8 字 → 结算 → 刷新校验持久化 → 三档进度独立）+ `node src/pinyin-typing/smoke.test.js`（取字优先级、判键、星级计算、存档读写与损坏恢复、字库数据合法性断言）。
